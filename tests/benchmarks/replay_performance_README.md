# Replay performance validation

These scripts are opt-in integration benchmarks, not unit tests. They require the full local website bundle, including generated replay HTML, exported trial/trajectory data, and captures. They do not train models, rewrite recordings, deploy, or change the user's preview server.

1. Start one `agent-browser` session with real WebGL enabled (`--args '--no-sandbox'` in this VM). Use its Chromium DevTools port from the session's `DevToolsActivePort` file as `CDP_PORT`. Keep unrelated 3D test browsers closed.
2. Start a separate fixture: `run-heavy node tests/benchmarks/replay_performance_fixture.mjs 59454`. It serves `web/` with Brotli quality 5 and browser cache rules from `web/vercel.json`, without replacing the normal preview. `REPLAY_WEB_ROOT` overrides the website root. An optional second argument freezes selected files from a snapshot directory while other files fall back to the website root.
3. Run an excluded warmup: `CDP_PORT=<port> BENCH_BASE=http://127.0.0.1:59454 run-heavy node tests/benchmarks/replay_performance_cdp.mjs warmup 1`. This precompresses responses and warms the software driver. Snapshot the baseline files before implementation, or do not change code between baseline runs.
4. Measure three rounds: `CDP_PORT=<port> BENCH_BASE=http://127.0.0.1:59454 run-heavy node tests/benchmarks/replay_performance_cdp.mjs baseline 3`. Add `BENCH_THROTTLE=1` and use a distinct stage name for 4 Mbps / 40 ms CDP network emulation. The script explicitly resets throttling when that flag is absent. Results are written to `/tmp/replay-<stage>-metrics.json`.
5. Fixed-pose visual checks: `CDP_PORT=<port> BENCH_BASE=http://127.0.0.1:59454 run-heavy node tests/benchmarks/replay_performance_quality.mjs baseline`. These temporarily seed `Math.random` to make procedural track textures comparable, seek to 0 / 0.8 / 2 seconds, capture screenshots, record pose/camera/results, and sample GC'd heap usage. The seed instrumentation is removed on success. Results and PNGs are under `/tmp/replay-<stage>-*`.
6. Repeat each stage separately after correctness checks and asset generation complete. Do not overlap measured runs with heavy builds/tests. Close the browser and stop only the fixture process you started afterward.

Shared-asset failure check (after timing, in the same disposable browser): `CDP_PORT=<port> BENCH_BASE=http://127.0.0.1:59454 run-heavy node tests/benchmarks/replay_performance_asset_failure.mjs priority3`. The optional stage name controls the `/tmp/replay-<stage>-asset-failure.json` output (default `priority1`). It blocks engine and meshes in turn using CDP, requires visible errors/disabled Play, then clears the blocking rule and checks reload recovery. If interrupted before cleanup, clear the CDP blocked-URL rule or close the disposable browser before continuing.

Persistent-renderer correctness (after priority 3): `CDP_PORT=<port> BENCH_BASE=http://127.0.0.1:59454 run-heavy node tests/benchmarks/replay_performance_persistent_correctness.mjs`. It checks renderer identity, reset-to-zero/pause on changed policy sets, Back/Forward, focus-only preserved time and network silence, failed capture and retry, superseded requests, eight-policy order/stall behavior, Replay restart, and 20 remove/re-add cycles with GC'd heap samples. Do not include these diagnostic timings in the performance medians. This script intentionally manipulates the disposable test browser's network conditions and history, not the website data.

Compact results: `node tests/benchmarks/replay_performance_summarize.mjs /tmp/replay-summary.json baseline baseline-4mbps priority1 priority1-4mbps priority3 priority3-4mbps`. This retains every measured sample and median, omits large raw resource/request payloads, and includes the persistent-renderer correctness/churn summary when available. Use three measured rounds per stage; the summary median calculation assumes an odd sample count. Never include warmup stage names in reported medians.

The benchmark exercises fallen Luna trial 2 policies 9 and 8 and moving winning GLM trial 2 policies 9 and 6. It clears HTTP cache before each cold page navigation, then adds/removes/re-adds the second policy. Readiness is the parent `g1:policies-state` event, not the later diagnostic collection completion. Network bytes are CDP encoded wire bytes, not raw file size; browser cache requests can appear in request counts with zero transferred bytes. The raw request `cache` field reflects CDP `fromDiskCache` only: memory-cache hits can have `cache: false` with zero bytes. Use wire bytes and Resource Timing together, not that disk-only flag, when checking shared script reuse.

Interpretation limits: software SwiftShader timings are not user-GPU timings; CDP network emulation is not a real phone/network; the fixture emulates response compression and browser cache headers, not the Vercel CDN or edge platform. Heap snapshots across navigations can include retained browser history and should not be presented as a GPU-memory budget. Use explicit cache/actor diagnostics and repeated same-page churn to verify persistent-renderer bounds.
